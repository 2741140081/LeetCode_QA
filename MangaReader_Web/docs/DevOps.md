### 09-07 need validate: 实现通过邮箱找回密码功能，核心在于构建一个安全、闭环的身份验证流程。
该流程主要包含请求发起、令牌生成与发送、链接/验证码验证、以及密码重置四个关键阶段。以下是详细的设计思路与实现要点：

1. 核心流程设计

第一阶段：用户发起请求‌, 需要在登录界面添加找回密码按钮, 然后跳转到找回密码页面, 输入用户名和邮箱地址.

输入校验‌：前端需对邮箱格式进行正则校验。后端接收请求后，首先检查该用户名和邮箱是否在系统中注册。
若未注册，出于安全考虑（防止枚举攻击），通常返回模糊提示如“如果该邮箱已注册，我们将发送重置链接”。
频率限制‌：为防止恶意刷接口，需对同一邮箱或IP地址设置发送频率限制（如每分钟最多1次，每天最多5次）。

第二阶段：生成安全令牌并发送邮件‌

生成Token‌：使用UUID或安全的随机数生成器创建一个唯一的、不可预测的重置令牌（Reset Token）。
存储Token‌：
推荐方式‌：将Token作为Key，用户ID或邮箱作为Value，存入Redis等缓存中间件，并设置较短的过期时间（如15-30分钟）。
构建重置链接‌：生成包含Token和用户标识（如加密后的邮箱或用户ID）的URL，例如 https://yourdomain.com/reset-password?token=xyz&email=encoded_email。
发送邮件‌：Spring Boot的JavaMailSender，通过SMTP协议将包含重置链接或验证码的邮件发送给用户。务必启用SSL/TLS加密传输以保障通信安全。

第三阶段：用户点击链接/输入验证码‌

验证Token有效性‌：后端接收请求后，从缓存中查找对应的Token。
若Token不存在或已过期，返回“链接已失效”错误。
若Token存在，校验通过，允许用户进入密码重置页面。
一次性使用‌：验证成功后，应立即从缓存中删除该Token，防止重放攻击。

第四阶段：设置新密码‌

密码强度校验‌：前端和后端均需对新密码进行强度检查（如长度至少8位，包含大小写字母、数字及特殊字符）。
一致性校验‌：确认两次输入的密码一致。
密码加密存储‌：严禁明文存储密码。使用BCrypt等强哈希算法对 newPassword 进行加密后存入数据库。
会话处理‌：密码重置成功后，可选地使该用户其他设备的登录会话失效，强制重新登录，以提升安全性。
2. Java技术实现关键点
   依赖引入‌：在Maven项目中引入 spring-boot-starter-mail 用于邮件发送，spring-boot-starter-data-redis 用于Token缓存（或使用Caffeine作为轻量级替代）。
   邮件配置‌：在 application.yml 中配置SMTP服务器地址（如smtp.qq.com, smtp.163.com）、端口（587或465）、用户名及授权码（注意不是登录密码，而是邮箱服务商提供的专用授权码）。
   异步发送‌：邮件发送属于IO密集型操作，建议使用 @Async 注解或消息队列异步执行，避免阻塞主线程，提升用户响应速度。
   异常处理‌：捕获 MessagingException 等异常，记录日志，并向用户返回友好的错误提示，避免暴露系统内部细节。
3. 安全性最佳实践
   Token时效性‌：重置链接必须有过期时间，建议设置为15-30分钟。
   防暴力破解‌：对重置密码接口实施限流策略。
   HTTPS‌：整个重置流程必须在HTTPS环境下进行，防止Token在传输过程中被窃听。
   信息脱敏‌：在日志中不要记录完整的Token或用户密码。

通过上述流程设计，可以确保用户在忘记密码时能够安全、便捷地恢复账户访问权限，同时有效抵御常见的网络攻击。

4. 需要构建邮件发送表, 使用定时任务扫描的方式来发送邮件
