一、漫画表 (manga)

```sql
CREATE TABLE manga (
    id            BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    name          VARCHAR(255) NOT NULL COMMENT '漫画名称/标题',
    dir_id        VARCHAR(20)  NOT NULL UNIQUE COMMENT '本地磁盘目录ID, 如 "11258"',
    author        VARCHAR(100) DEFAULT '' COMMENT '作者',
    description   TEXT         DEFAULT '' COMMENT '简介/描述',
    cover_image   VARCHAR(255) DEFAULT '' COMMENT '封面图片相对路径, 如 "001/img001.webp"',
    status        TINYINT      NOT NULL DEFAULT 0 COMMENT '0:启用 1:禁用 2:待下载',
    created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    INDEX idx_name (name),
    INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='漫画主表';
```

> 索引说明：
> - `dir_id` 已设为 `UNIQUE`，自带唯一索引，无需额外建索引
> - `name` 已有普通索引 `idx_name`
> - `status` 加索引方便按状态筛选漫画列表

二、章节表 (chapter)

```sql
CREATE TABLE chapter (
    id            BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    manga_id      BIGINT UNSIGNED NOT NULL COMMENT '所属漫画ID',
    chapter_num   INT UNSIGNED   NOT NULL COMMENT '章节序号, 如 1,2,3 (对应目录 "001","002")',
    title         VARCHAR(255)  DEFAULT '' COMMENT '章节标题',
    image_count   INT UNSIGNED  DEFAULT 0 COMMENT '图片数量',
    created_at    DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
    
    UNIQUE KEY uk_manga_chapter (manga_id, chapter_num),
    INDEX idx_manga_id (manga_id),        -- ★ 核心索引: 按漫画查章节
    INDEX idx_chapter_num (manga_id, chapter_num)  -- 复合索引覆盖 uk，但保留便于范围查询
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='章节表';
```

> `manga_id` 是否需要索引？
>
> 必须要。 虽然 `(manga_id, chapter_num)` 联合唯一索引的最左前缀可以覆盖 `manga_id` 的等值查询，但：
> - 显式建 `INDEX idx_manga_id` 语义更清晰
> - 当查询仅按 `manga_id` 做 `ORDER BY chapter_num` 或范围扫描时，单独索引有时更优
> - 实际测试中两者性能接近，显式建索引属于良好实践
>
> 结论：建议加上 `INDEX idx_manga_id (manga_id)`

三、漫画图片表 (manga_image)

```sql
CREATE TABLE manga_image (
    id              BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    chapter_id      BIGINT UNSIGNED NOT NULL COMMENT '所属章节ID',
    image_name      VARCHAR(100)   NOT NULL COMMENT '图片文件名, 如 "img001.webp"',
    image_type      VARCHAR(10)    NOT NULL COMMENT '图片类型: jpg/jpeg/png/webp/gif',
    image_width     INT UNSIGNED   DEFAULT 0 COMMENT '图片宽度(px)',
    image_height    INT UNSIGNED   DEFAULT 0 COMMENT '图片高度(px)',
    image_url       VARCHAR(100)   NOT NULL COMMENT '图片存储路径, 如 "12560/001/img001.webp"',
    download_url    VARCHAR(500)   DEFAULT '' COMMENT '下载地址',
    download_status TINYINT        NOT NULL DEFAULT 0 COMMENT '0:已下载 1:未下载 2:下载失败',
    sort_order      INT UNSIGNED   NOT NULL DEFAULT 0 COMMENT '图片在章节内的排序序号',
    created_at      DATETIME       NOT NULL DEFAULT CURRENT_TIMESTAMP,
    
    INDEX idx_chapter_id (chapter_id),                    -- ★ 核心索引: 按章节查图片
    INDEX idx_download_status (download_status),          -- 按下载状态筛选
    INDEX idx_chapter_sort (chapter_id, sort_order)       -- 按章节+排序查图片(阅读用)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='漫画图片表';
```

> `chapter_id` 是否需要索引？
>
> 必须要，而且是最重要的索引。 原因：
> - 阅读时需要按 `chapter_id` 查出该章节所有图片并按 `sort_order` 排序
> - 没有索引会导致全表扫描，图片量大时性能极差
> - `(chapter_id, sort_order)` 复合索引直接覆盖阅读场景（避免排序开销）
>
> 结论：必须建 `INDEX idx_chapter_id (chapter_id)` 和 `INDEX idx_chapter_sort (chapter_id, sort_order)`

四、阅读进度表 (reading_progress)

```sql
CREATE TABLE reading_progress (
    id            BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    user_id       BIGINT UNSIGNED NOT NULL COMMENT '用户ID(如有用户系统), 或设为设备标识',
    manga_id      BIGINT UNSIGNED NOT NULL COMMENT '漫画ID',
    chapter_id    BIGINT UNSIGNED NOT NULL COMMENT '章节ID',
    image_index   INT UNSIGNED    NOT NULL DEFAULT 0 COMMENT '当前阅读到该章节的第N张图片(从0开始)',
    total_images  INT UNSIGNED    NOT NULL DEFAULT 0 COMMENT '该章节总图片数(缓存,方便计算百分比)',
    progress_pct  DECIMAL(5,2)    NOT NULL DEFAULT 0.00 COMMENT '该章节阅读进度百分比 0~100',
    last_read_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '最后阅读时间',
    created_at    DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at    DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    UNIQUE KEY uk_user_manga_chapter (user_id, manga_id, chapter_id),  -- 同一用户同一漫画同一章节唯一一条
    INDEX idx_user_manga (user_id, manga_id)                            -- 按用户查所有漫画进度
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='阅读进度表';
```

> 设计要点：
> - `UNIQUE KEY` 保证同一用户对同一漫画同一章节只有一条进度记录
> - `image_index` 记录精确到第几张图，恢复阅读时直接跳转
> - `progress_pct` 缓存百分比，列表展示时无需实时计算
> - 如果没有用户系统，`user_id` 可以用设备指纹/UUID/固定值代替

五、书签表 (bookmark)

```sql
CREATE TABLE bookmark (
    id            BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    user_id       BIGINT UNSIGNED NOT NULL COMMENT '用户ID',
    manga_id      BIGINT UNSIGNED NOT NULL COMMENT '漫画ID',
    chapter_id    BIGINT UNSIGNED NOT NULL COMMENT '章节ID',
    image_index   INT UNSIGNED    NOT NULL DEFAULT 0 COMMENT '书签所在图片序号(从0开始)',
    bookmark_name VARCHAR(100)   DEFAULT '' COMMENT '书签名称/备注(用户自定义)',
    color_tag     VARCHAR(10)    DEFAULT '' COMMENT '书签颜色标签, 如 "red","blue"',
    created_at    DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    
    INDEX idx_user_manga (user_id, manga_id),        -- 按用户查某漫画的所有书签
    INDEX idx_user_bookmark (user_id, created_at)     -- 按用户按时间查书签列表
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='书签表';
```

> 设计要点：
> - 一本漫画可以有多个书签，所以不设唯一约束（除非你想限制每章节只能一个）
> - `bookmark_name` + `color_tag` 让用户能自定义备注和颜色分类
> - 如果想限制每章节只能一个书签，加：`UNIQUE KEY uk_user_manga_chapter (user_id, manga_id, chapter_id)`

七、索引汇总速查

| 表 | 索引名 | 字段 | 用途 |
|---|---|---|---|
| manga | `idx_name` | name | 按标题搜索漫画 |
| manga | `idx_status` | status | 按状态筛选 |
| chapter | `idx_manga_id` | manga_id | 查某漫画的所有章节 |
| chapter | `uk_manga_chapter` | (manga_id, chapter_num) | 防重复 + 联合查询 |
| manga_image | `idx_chapter_id` | chapter_id | 查某章节的所有图片 |
| manga_image | `idx_chapter_sort` | (chapter_id, sort_order) | 按序读取图片 |
| reading_progress | `uk_user_manga_chapter` | (user_id, manga_id, chapter_id) | 防重复 + 精确查询 |
| bookmark | `idx_user_manga` | (user_id, manga_id) | 查某漫画的书签 |
